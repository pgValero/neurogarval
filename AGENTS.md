# AGENTS.md

Single-page marketing site for NeuroGarval (Spanish psychology practice). No package manager, no tests. There IS a minimal build step: Pages CMS edits YAML in `content/`, and `build.py` injects it into the HTML templates.

## Layout & deploy

- `src/index.html` — site template (HTML + JSON-LD); content between `<!-- pages:begin NAME -->` / `<!-- pages:end NAME -->` markers is **regenerated by `build.py`** — do not hand-edit text inside markers; edit it in Pages CMS (`content/*.yml`) instead. Domain/base URLs, logo, SEO/Open Graph, JSON-LD and both navigation menus are fixed outside those markers. No inline `<style>`/`<script>`; do not introduce a framework or bundler.
- `src/firma.html` — standalone email signature template (not linked from the site); same marker system (3 regions); the fixed logo uses an absolute `https://neurogarval.es/media/...` URL.
- `src/styles.css` — all site CSS, linked in `<head>`.
- `src/script.js` — classic (non-module) script at end of `<body>`; **only** opens/closes the service and modality modals (content from `window.SITE_DATA`, loaded from `data.js` before it) and toggles the mobile menu. It injects no data: contact is written into the HTML by `build.py`. Inline `onclick` handlers rely on top-level functions staying global.
- `content/` — YAML edited via Pages CMS: `settings.yml` (contact/footer, read-only in the CMS), `home.yml` (page sections + Markdown content for cards, modals, specialist, blog and FAQ), `firma.yml` (signature copy).
- `media/` — source static resources (images, `favicon.svg` and PDFs `aviso_legal.pdf`/`tarjeta.pdf`); the build keeps the current public structure by publishing the favicon and PDFs at the `_site/` root and the images under `media/`. Consultation-photo fields in the clinic modality are editable from Pages CMS and fall back to an icon while empty.
- `.pages.yml` — Pages CMS config (collections, fields, media paths). Commented in Spanish. Los campos largos de la página son `rich-text` con `format: markdown`; los títulos, botones y metadatos siguen siendo campos simples.
- `build.py` — generator: reads `content/*.yml`, converts Markdown to HTML, renders the 19 regions of `src/index.html` + the 3 of `src/firma.html`, writes contact data into the `.neuro-*` slots of the generated `index.html`, and writes `_site/` with the current public structure (site files and favicon/PDFs at its root, images under `media/`) plus generated `data.js`. Requires Python + PyYAML + Markdown. `_site/` is gitignored.
- `.github/workflows/deploy.yml` — on push to `main` (or manual dispatch): runs `build.py` and publishes `_site/` with Actions.
- `CNAME` — `neurogarval.es`; host is GitHub Pages. **Repo Settings → Pages must be set to source "GitHub Actions"** (once), after which pushing to `main` deploys production.

## Conventions

- All user-facing copy is **Spanish**. Write edits in Spanish; commit messages are in Spanish too.
- Contact and footer data live in `content/settings.yml` → `build.py` writes the contact **directly into the HTML** (`.neuro-phone`, `.neuro-mail`, `.neuro-address`, and tel/WhatsApp/mailto/Maps links) in every place it's needed, and into the generated `firma.html`. Both objects are read-only in Pages CMS; their address and footer text lists each require exactly two fixed items, so they cannot be added, removed, or reordered there. To change them, edit `settings.yml` in the repository; because JSON-LD is fixed in `src/index.html`, update its hardcoded phone and address there too when necessary. No JS is involved; `data.js` only carries modal content (`services`, `modalities` and `icons`).
- Service cards call `openServiceModal(index)` and modality cards call `openModalityModal(index)`; modal copy comes from the corresponding `SITE_DATA` collection, not from card HTML. Consultation photos are configured per modality item in `content/home.yml`; the standalone gallery section no longer exists. The "blog" section is placeholder content.
- Regions are index-matched between `.pages.yml` and `build.py`: if you add/rename a region in one, mirror it in the other.

## Verifying

- Build locally: `python build.py` (needs `pip install pyyaml markdown`), then open `_site/index.html` in a browser — never open `src/index.html` directly: its `.neuro-*` contact slots are empty until `build.py` fills them.
- Lint: `prek run --all-files` (HTMLHint, Stylelint, ESLint, Lychee). Lychee has excludes for `data\.js` (generated, line too long), for source-relative assets in `src/`, and for `neurogarval.es/media/` URLs until the media files are live.
- Check section by section (`#inicio`, `#servicios`, `#modalidades`, `#proceso`, `#especialista`, `#blog`, `#faq`, `#contacto`), a service modal, each modality modal, and the mobile menu.
- `src/index.html` (~530 lines), `src/styles.css` (~845 lines), `src/script.js` (~90 lines); prefer targeted `Edit` calls over `Write`.
